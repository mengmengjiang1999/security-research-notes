# SFuzz: Slice-based Fuzzing for Real-Time Operating Systems

## 问题

RTOS 固件常被编译为缺少符号的单体二进制，不同厂商的外设又难以统一仿真。全系统模糊测试需要处理大量与输入无关的路径，纯静态分析则容易遇到路径爆炸与语义恢复问题。

## 核心方法

SFuzz 利用 RTOS 任务通常功能单一、控制流相对独立的特点，从处理外部输入的函数出发构造代码切片，再对切片执行覆盖率引导的模糊测试。系统由四个主要部分组成：

1. 前向切片器：从输入处理函数构造调用图和执行树，剪除与外部输入无关的路径。
2. 控制流节点处理器：处理缺失运行时上下文时的函数调用和条件分支。
3. 微型模糊测试：在指令级仿真中聚焦输入相关切片，并监控危险的 sink 函数调用。
4. 混合执行分析：结合前向与后向切片恢复路径约束，验证模糊测试报警。

## 结果与启示

原文在 11 个厂商的 35 个 RTOS 固件样本上评估，报告发现 77 个未知漏洞。这项工作的关键启示是：当全系统仿真成本过高时，可以先缩小到输入相关的功能切片，再用动态测试与约束求解互相补强。
